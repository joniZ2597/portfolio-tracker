## Lessons
- [backlog] The protected-candidate final-QA overlay (shared clone + reset to the task base + worktree files + candidates + `node_modules`) was assembled by hand and needed four fixes (no `.git` for the fixture-template suite, wrong HEAD/empty index from `--no-checkout`, stray ignored files, missing `node_modules`); a small documented helper in `qa/tools/` would remove that — pending routing
- [backlog] `qa/fixture_template_offline.js` runs `git show <historic commit>:…` at load, so it cannot run in any `.git`-less copy; a note in its header would save the setup crash — pending routing
- [design] The suites that digest the tool and integrity module (`git_contract`, `fixture_template`) are red in the real worktree for the whole interval between the ordinary commit and step 13a for any task that changes a protected file; a task of this shape must validate in an overlay or accept the interval.
- [backlog] The same swallowed-unlink pattern (`try { fs.unlinkSync(<approval>) } catch (e) { /* already gone */ }` followed by a success audit line) exists in the other single-use approval paths of the land tool (LAND, PUSH, PROTECTED, BRIEF); review them separately for fail-closed behaviour and for a rollback that cannot itself fail silently — pending routing
- [backlog] Record rollbacks in the land tool (`task-start`, `adopt`) are best-effort `unlink`s; if a rollback unlink fails the refusal is returned with the record left behind (Codex round-2 finding, Owner-deferred accepted residual) — a stricter rollback (verify absence, or report R-REC STOP) and a test that makes the rollback unlink fail belong in a follow-up — pending routing
- [local] Run `auto_mode_hardening_offline` alone: in parallel with a long suite it can lose a real-git row (AH-16, AH-19-13) to the fail-closed git budget.
- [local] `grep -c $'\r'` is not a CRLF audit; the byte audit (`CRLF`, lone LF, lone CR counts via node) was used for every ordinary file.
